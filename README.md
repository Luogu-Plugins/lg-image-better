# 洛谷粘贴图片自动上传

在洛谷文字编辑区粘贴截图或图片文件，脚本在原位置插入占位符，自动识别验证码、上传至洛谷图床，并替换为 `![](图片地址)`。一次多图、连续粘贴使用串行队列，上传期间可以继续输入。

## 安装

1. 在浏览器中安装并启用 Tampermonkey。
2. 打开 Tampermonkey 控制面板，创建新脚本。
3. 将 `luogu-paste-image.user.js` 的完整内容粘贴进去，替换默认模板并保存。
4. 登录洛谷、刷新页面，在文字编辑区粘贴一张截图。

右下角显示任务状态。上传成功后自动插入 Markdown，也可复制链接；失败时原位置保留失败占位符，可点击“重试”或“移除”。网络中断或上传超时的任务会提示先检查图床，避免重复上传。

## 验证码与重试

- 模型来源于用户提供的 Amazing Luogu 1.3.9 脚本中引用的 `https://cdn.amlg.top/amlg/OCRCaptcha.js`。
- 依次尝试本脚本缓存、当前运行的 Amazing Luogu 暴露的 `OCRCaptchaCode` 缓存、上述模型资源下载。也可通过 Tampermonkey 菜单导入 `.js` 或 `.json` 模型文件。
- 使用 TensorFlow.js 4.22.0 在浏览器本地推理，输入为 90 × 35 RGB，输出为四位字符。不会把验证码发往第三方识别服务。
- 模型资源只解析 JSON 字面量，不执行其中的 JavaScript。支持 `MODEL_TOPOLOGY`、`WEIGHT_SPECS`、`WEIGHTS_BASE64` 三项数据；不支持通过函数动态生成数据的模型资源。
- **首次尝试 + 最多 5 次重试 = 最多 6 次。** 每次验证码失败后冷却 1000ms，再获取新验证码。用尽次数后报告“验证码识别失败，已重试 5 次”。
- 未登录、配额/权限错误、模型加载失败、限流和上传网络错误不会算作验证码识别错误并反复请求。

## 编辑器范围

- 原生可写 `textarea`，排除明确标为源代码的输入区及 Monaco/Ace 编辑器。
- CodeMirror 5 的 Markdown/GFM 模式。
- 洛谷当前 Casketstar 的 `.cs-editor` 包装内 CodeMirror 6，以及可识别的 Markdown 包装内 CodeMirror 6；需能获取其 EditorView。
- 未适配的富文本编辑器保留默认粘贴行为。输入框、密码框、网页 HTML 中的远程图片链接不自动上传。

上传期间删除占位符或关闭编辑器，脚本不会在别处插入结果；若图片已经上传，任务栏会保留可复制的链接。撤销占位符也可能取消待上传任务。若将占位符复制成多个，脚本不会猜测替换位置。

专用编辑器通过编辑器事务修改。原生 textarea 初次插入优先使用浏览器原生插入；后台替换会通知页面 `input` 和 `change`，但其撤销历史取决于浏览器，不能保证所有 textarea 都能一步撤销后台替换。

## 菜单与水印

Tampermonkey 菜单提供：开关自动上传、设置水印类型、清除模型缓存、导入模型。

默认水印类型为 **1**，与检查到的洛谷当前图床页面默认值相同。设置为 0 会关闭水印。当前前端说明：超过 512000 字节的图片或无水印图片占用高级空间；是否具有额度由洛谷服务器判定。脚本保留原始图片，不自动压缩、裁剪或转换 GIF。

## 隐私与依赖

图片和验证码请求使用现有洛谷登录状态。仅图片上传到洛谷返回的指定存储地址；存储上传不发送账号 Cookie 或 CSRF token。

额外依赖：固定版本 TensorFlow.js（jsDelivr），以及 Amazing Luogu 模型资源。脚本不需要其他 Amazing Luogu 功能；复用其缓存是可选的。模型及外部依赖的权利归各自提供方，未在本仓库中重新分发模型权重。

## 开发与验证

源码位于 `src/core.mjs` 和 `src/browser.js`。Node.js 24 下无需安装 npm 依赖：

```sh
node scripts/build.mjs
node --check luogu-paste-image.user.js
node --test --test-isolation=none tests/core.test.mjs tests/browser.test.mjs
```

测试覆盖完整模拟粘贴流程、当前上传协议、继续输入、占位符删除、编辑器事务、验证码重试上限/间隔、取消、队列失败后继续、模型解析及上传回调。测试使用模拟模型与网络响应，不代表实际模型准确率。

**当前验证边界（2026-10-10）：** 已从洛谷当前公开前端及配置确认上传流程，并通过自动测试；本机未能连接已登录的浏览器，模型资源下载连接超时，尚未完成真实账号上传和真实模型推理联调。如果浏览器也无法下载模型，需要复用已有 Amazing Luogu 模型缓存，或从可访问该资源的环境取得文件后导入。

接口依据见 `docs/interface-notes.md`。
